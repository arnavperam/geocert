# Prospective external acquisition — not executed here

The supplied paper uses the original lung crops and the explicitly identified breast **format-test** crops. These scripts do not contribute any reported result.

`release/acquire.yml` can be copied into the repository's `.github/workflows/acquire.yml` and dispatched after the source is committed. It retrieves selected ZIP members rather than morphology images, records each retrieved file's hash, selects two 200-µm cores by a seeded permutation of cell centroids (seed 20261028, at least 30 centroids/core), adds a 100-µm context halo, and attempts five Proseg 3.2.0 runs per core. Lung candidates overlapping the existing regions plus a 100-µm guard are excluded. Crop selection is written before transcript or segmentation outcomes are examined. Failures remain failures; the script does not silently disable factorization or replace failed replicates.

The breast URL is the replicate-1 archive linked by the official `10XGenomics/janesick_nature_comms_2023_companion` README. It differs from both the two-FOV format-test archive used in the present paper and the separate custom-100-gene breast listing. The lung archive is the output bundle corresponding to the dataset named in the supplied source metadata (the metadata itself links its landing page). The direct archive path is also documented in the Cartloader Xenium example. Download metadata is selective-member provenance, not an uncomputed checksum for the entire remote archive.

The workflow has not been dispatched or validated against live external data in this session. The HTTP-range utility fails closed if the source ignores byte ranges. Future comparison also requires a validated source-mask/coordinate adapter (the older breast release may supply polygons rather than the current raster bundle). Acquiring tables or running Proseg does not by itself validate Atlas geometry, anatomical truth, or a new count certificate. No future acquisition result is asserted in the manuscript.
